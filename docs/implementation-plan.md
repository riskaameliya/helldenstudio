## Verification and acceptance

- **Vitest** under `tests/unit/`. Cover unique and invalid room IDs, invalid floor or bounds, coordinate conversion including signed depth, binding of all room IDs to their floor meshes, and the building → floor → room → return state sequence. Assert the floor list counts are nine and three. Test deterministic camera ownership after explicit selection without WebGL.
- **Playwright** under `tests/e2e/`. Check all seven landmarks or named sections, hero anchor, both floor controls, room selection and return with keyboard and pointer, accessible feedback, and the verified booking link. Exercise reduced motion, narrow and wide viewports, WebGL-disabled startup, blocked GLB requests, and no-JS floor index. Exercise context loss and a WebGL happy path in a supporting browser. Run core coverage in Chromium, Firefox and WebKit. Review touch and rendering on a representative real mobile device.
- **Visual and accessibility checks.** Review at roughly 360, 768 and 1440 CSS pixels. Require zero page-level horizontal overflow, usable room controls, visible focus, readable overlays and WCAG 2.2 AA contrast for applicable pairings. Manually review heading order, legends, screen-reader announcements and tab flow.
- **Performance checks.** Use a production build. Confirm no Three.js bundle or GLB request during initial navigation before Anatomy qualifies for loading. Confirm one canonical model request and that the canvas goes idle when settled. Record mobile scroll and camera frame timing, first-load transfer and layout stability. Proposed goals are p75 LCP ≤ 2.5s, INP ≤ 200ms and CLS ≤ 0.1 where field data exists. Record lab conditions separately and profile the reference device before deciding any further effects.
- **Proposed quality commands.** Wire `npm run lint`, `npm run format:check`, `npm run typecheck`, `npm run test:unit`, `npm run build`, and `npm run test:e2e`. Test browser behavior against the production server before release.

## Risks and decisions for review

| Risk                                                    | Mitigation or decision                                                                                                                                                 |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Model orientation and floor occlusion                   | Confirm accessors, transform once, then review entrance and side orientation in-browser. Test floor groups against actual named nodes before integrating the reveal.   |
| Conceptual geometry could be mistaken for a survey      | Keep the concept-model label visible, with no measured claims. Preserve the confirmed arrangement and validate against room configuration.                             |
| Motion can fight user intent                            | One camera owner at a time. Manual selection wins, normal scrolling continues, and reduced motion bypasses tweening.                                                   |
| Mobile GPU variability                                  | Keep on-demand rendering and capped pixel ratio. Test on real hardware and keep HTML room exploration active on rendering failures.                                    |
| Photos, wording and booking information are outstanding | Continue sequencing and technical work after plan approval. Require approved real photography, room copy, brand details and a verified destination for public release. |
| Dependency drift and duplicate GLBs                     | Verify peer ranges before installation. Use the lockfile and publish one runtime GLB. Preserve source provenance when reorganizing.                                    |
| Workspace skills currently ignored by Git               | Decide later whether to track only Hellden-specific skills. Keep that decision separate from the app migration.                                                        |
